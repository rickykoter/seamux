## The goal

deep-plan's remote features (state branches, families, export and import of
state) have no shared memory. Beads (`bd`, github.com/steveyegge/beads) is a
dependency-aware issue tracker built for coding agents. Explore adding it as
an **optional add-on**: off unless installed, and off unless a repo opts in.

What a memory layer would add that deep-plan lacks today:

1. **Side findings.** A bug or idea found mid-increment that doesn't belong
   in this plan has no home: it goes into the spec or gets lost. Beads links
   items with "discovered-from".
2. **Work other agents can see.** A plan as an epic, increments as child
   items, a workstream's `after` as "blocks" dependencies, so `bd ready`
   shows other tools what is unblocked.
3. **Memory that outlives the sandbox.** Cloud sessions lose `~/.claude`.

About Beads (from its pkg.go.dev docs, v0.63 to v1.2; check what is current):
a Go CLI on a Dolt database. The default embedded mode has one writer;
server mode allows several. `.beads/issues.jsonl` is an export only, not the
source of truth. Sync between machines goes through Dolt remotes, and git is
optional. `bd init` writes AGENTS.md guidance and installs Claude Code hooks.

## The shape so far: a separate plugin

Working name "logbook" (sea-themed, like lookout). Ask the human about it.

- **Its own plugin**, not a deep-plan feature: one plugin per feature (ADR
  0004), and deep-plan reaches another plugin only through its CLI (ADR
  0013, the lookout precedent).
- **Needs no deep-plan change in v1.** It reads `deep-plan status --json`,
  already a stable seam the crew board consumes (deep-plan/DEVELOPING.md,
  "Integration seams").
- **Plans copied out.** Its own hooks (SessionStart, PostToolUse on Bash
  commands that mention `deep-plan go|done|block|reset|deliver|close`, and
  Stop) compare `status --json` with a saved cursor and update Beads through
  `bd --json`, never Dolt directly. Items are labeled with plan and
  increment, so updates can safely repeat.
- **Notes come back in.** `logbook note "..."` files an item linked to the
  current increment. A UserPromptSubmit hook adds that plan's open notes as
  `additionalContext`, marked as data, not instructions (the same rule as
  page annotations in deep-plan/references/sharing.md).
- **Opt-in twice.** Installed through install.sh, and active only in a repo
  with `.seamux/logbook.json` (the pattern of `.seamux/lookout.json` and
  `.seamux/observability.json`). A bash fast path, like
  `deep-plan/hooks/news.sh`, keeps other repos off node.
- **Cloud sessions:** its own `install-repo`, a twin of
  `lookout/lib/install.mjs`, with hooks guarded on `CLAUDE_CODE_REMOTE`.

## Lines it must not cross

- **Never in the gate's path.** The gate costs about 45 ms per call
  (DEVELOPING.md) and fails open on missing state.
- **A Beads item never authorizes.** "Ready" is advice. `go` stays the
  person's, or the parent agent's for a delegated child (ADR 0028).
- **No answer keys.** Reading only `status --json`, and never the keys
  folder, means it can't leak them. Keep it that way.
- **No writes into deep-plan's state, keys or ext folders.** The gate refuses
  those (deep-plan/lib/state.mjs, near line 1290). Logbook keeps its cursor
  in its own folder.
- **If `bd` is missing or its remote is down,** warn once and leave deep-plan
  unchanged.

## Leads to verify

- `deep-plan/lib/ext.mjs:28`: no hook fires on a transition, by choice (the
  old Jira auto-sync was on 1 of 12 plans).
- `deep-plan/lib/ext.mjs:38`: `EXT_DIR` is always under the home folder. Unlike
  state, it doesn't move into the repo on the remote host
  (`deep-plan/lib/state.mjs:19-23`), so an ext verb is lost with a cloud
  sandbox. That is why an ext verb was ruled out.
- `deep-plan/lib/sync.mjs:23-31`: the state-branch storage interface, "so an
  object store can stand in for git later". Dolt could fit here, but the idea
  was dropped: it would make gate state depend on an outside database.
- `deep-plan/lib/merge.mjs:52` (`mergeStates`) and `:105` (`mergeLines`):
  how concurrent pushes merge today.
- `deep-plan/references/families.md`: news is pulled at the next prompt,
  never pushed (ADR 0012); a remote child's `await-go` polls its branch every
  15 s. Logbook's notes hook should follow the pull rule.
- `install.sh:40` and `:57`: every plugin installs by default, with a
  `--no-<plugin>` opt-out. Logbook needs an outside binary, so it may need
  the opposite default.
- `docs/adr/0026-*`: the house chose stdlib SQLite to avoid dependencies;
  `bd` plus Dolt is a new kind of dependency.

## Open questions for the human

1. Do you use Beads now, in any repo? If not, is the appeal Beads itself or
   only shared memory? If only the memory, a Beads-shaped notes branch on the
   existing state-branch code needs no new dependency. It can't import
   deep-plan's `sync.mjs` across plugins (ADR 0004), so where would it live?
2. The name "logbook"?
3. v1 scope: plans copied out only, or notes coming back in as well?
4. Install default: opt-in `--logbook`, or on by default like the others?
5. Cloud: is installing `bd` in the environment's setup script, and allowing
   its Dolt remote through the network policy, acceptable?
6. Which Beads remote: DoltHub, a self-hosted server, or a file path?

## Costs already named

- An eighth plugin: its own probe, skill lint, evals baseline, CI,
  marketplace entry and `.seamux/verify.json` recipes.
- Claude Code runs an event's matching hooks in parallel, so at session start
  logbook may read before deep-plan's `state pull` finishes. The Stop hook
  catches up.
- Beads tracks issues, not general memory. Loose lessons ("this test is
  flaky") stretch how it's meant to be used.
